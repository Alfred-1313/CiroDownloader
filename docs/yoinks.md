# مسیر جایگزین yoinks

از نسخهٔ 1.11.0، مسیر اصلی دانلود با کوکی موجود اجرا می‌شود. وقتی کوکی وجود ندارد، ساختار آن نامعتبر است یا تلاش اصلی با خطای ورود/دسترسی/شبکه/استخراج شکست می‌خورد، مسیر جایگزین **yoinks** بدون کوکی اجرا می‌شود. راستی‌آزمایی کوکی تازهٔ واردشده هرگز به این مسیر منتقل نمی‌شود.

## کد مورد استفاده

توابع اصلی `probe` و `download` از [pablostanley/yoinks](https://github.com/pablostanley/yoinks)، نسخهٔ 0.3.1 و commit `6f03720813c22f907d3fb9ba98567f2169446b82`، بدون تغییر در `third_party/yoinks/src` نگه‌داری می‌شوند. مجوز MIT و نام صاحب اثر در همان پوشه آمده است. هنگام ساخت Docker، SHA-256 فایل‌های اصلی بررسی و TypeScript با ابزار داخلی Node به JavaScript تبدیل می‌شود. تغییر نسخهٔ واردشده باید همراه بازبینی منبع و به‌روزرسانی manifest باشد.

`bin/yoinks-adapter.mjs` به‌جای بازکردن رابط تعاملی ترمینال، همان توابع اصلی را فراخوانی می‌کند. برای دریافت فایل، yoinks ابتدا اطلاعات را با `probe` می‌گیرد و سپس از `download` و `--load-info-json` استفاده می‌کند. فرمت دقیق انتخاب‌شدهٔ کاربر به آن داده می‌شود؛ کاهش پنهانی کیفیت انجام نمی‌شود. فایل دریافتی برای کنترل کدک، ابعاد، حجم و آماده‌سازی تلگرام به مسیر مشترک FFmpeg برمی‌گردد.

`bin/yoinks-ytdlp.php` یک رابط `exec` برای باینری پین‌شدهٔ موجود است. تنظیمات بیرونی yt-dlp را نادیده می‌گیرد، کوکی نمی‌فرستد و همان پراکسی تنظیم‌شده را اعمال می‌کند. دانلود خودکار باینری از اینترنت و نصب رابط ترمینالی React/Ink استفاده نمی‌شوند. فایل اطلاعات موقت در پوشهٔ خصوصی همان کار قرار دارد و پس از عملیات پاک می‌شود. هر درخواست Node مستقل دارد؛ دانلودها و توقف آن‌ها زیر کنترل سرپرست فعلی Worker می‌مانند.

## تشخیص مسیر

در پوشهٔ نصب سرور:

```bash
docker compose logs --tail=40 worker
```

مسیر اصلی:

```text
YouTube provider=yt-dlp cookies=yes
```

مسیر جایگزین:

```text
YouTube provider=yoinks cookies=no
```

اگر مسیر اصلی شکست خورده باشد، علت کلی با `primary_reason` ثبت می‌شود. شکست مسیر جایگزین نیز با `provider=yoinks failed` ثبت می‌شود؛ لینک‌های امضاشده و توکن‌ها از پیام فنی پاک می‌شوند. اطلاعات کوکی در این پیام‌ها چاپ نمی‌شود.

## حدود نتیجهٔ آزمون

آزمون‌های محلی، خودِ توابع پروژهٔ yoinks را با انتقال یوتیوبِ جایگزین‌شده با فایل‌های محلی اجرا می‌کنند. پردازش واقعی FFmpeg، ارسال multipart به API محلی، ویدیو و MP3، گروه و چند درخواست هم‌زمان، و توقف فرایندها بررسی می‌شوند. این آزمون، ادعای موفقیت دانلود زنده روی IP سرور کاربر نیست.

yoinks خودش از yt-dlp استفاده می‌کند و مسیر شبکهٔ مستقلی برای دورزدن درخواست ورود یوتیوب ندارد. بنابراین ممکن است هر دو مسیر روی یک IP با خطای «Sign in to confirm you’re not a bot» مواجه شوند. نتیجهٔ واقعی باید بعد از نصب نسخه، با همان لینک و IP سرور آزمایش شود؛ داشتن کوکی معتبر یا مسیر خروجی قابل استفاده همچنان می‌تواند لازم باشد.
