# Verification

GitHub Actions runs these checks on each push:

- `php tests/run.php`: URL validation, admin authorization, queue limits, Persian help alerts, cookie export validation and redacted process/proxy errors.
- `php tests/cookies.php`: administrator-only imports with arbitrary TXT filenames, persistent waiting and same-message navigation; real downloader invocation against local metadata fixtures gates replacement, with expired cookies, YouTube rejection and network failures preserving the active jar.
- `php tests/posters.php`: poster URL validation, stored photo state across restarts, photo-caption edits, missing/rejected poster fallback, caption limits and cleanup after delivery.
- `php tests/ux_fixes.php`: upgrade of saved historical defaults, preservation of real custom captions, plain pre-delivery messages, Persian cookie diagnostics, private user statistics, legacy reply-button labels and active-update menu reopening.
- `php tests/quality_waiting.php`: no selection deadline or cancel row, migration of old waiting menus, immediate new links without cancelling previous choices, safe selection while another request is active, queue capacity based on actual work, and recreation of the previous release's unique index during rollback with multiple waiting menus and an active job. The real worker test also checks that an old unchosen menu remains untouched.
- `php tests/processing_limits.php`: default-off private/group limits, immediate requests during uploads, separate per-user/chat quotas, ownership, safe migration and rollback index initialization, atomic admission across processes, numeric editing and authorization, blue display headers with neutral controls, and the private-mode notice's return paths after editing.
- `php tests/personalization_scope.php`: traverse every editor group and page, include only UI ordinary users see, preserve captions and access notices, block admin field edits through callbacks, old routes and saved sessions, and retain user color/access controls.
- `php tests/personalization_recovery.php`: save and reset every user-editable field, verify persistence after restart, exercise all button colors and emoji, return to the selected catalog page, repair rejected saved previews, preserve edits across deleted messages and preview taps, and retain previous values after rejection or transport failure.
- `php tests/personalization_sections.php`: covers screen grouping, independent cover captions and qualities, backward-compatible shared button settings, layout changes, rejected previews, persistence, and administrator-only access.
- `php tests/admin_keyboard.php`: switching home/administration reply keyboards, actual routing of every tool, stopping/starting, returning from submenus, clearing pending input, old inline navigation and deletion failure, and denying forged public reply labels. A strict fake rejects reply keyboards on Telegram edit methods.
- `php tests/groups.php`: default-on group use, native invitation URL and neutral styling, editable invitation/user guides, refreshing displayed guides after toggles, ownership and chat validation, forum destinations, addressed commands, privacy-mode fallback, quiet handling of unrelated messages, keeping administrator state private, and combined Help length validation with safe rendering/refresh of oversized legacy settings.
- `php tests/media.php`: real FFmpeg processing of landscape MP4, 480x854 portrait Shorts and higher-resolution WebM; isolated cookie copies, bounded parallel fragment settings, YouTube proxy forwarding and real multipart HTTP file upload against a local test endpoint. Mixed-codec cases compare stream hashes to prove that suitable H.264 video or AAC audio is copied without re-encoding.
- `php tests/audio.php`: real AAC, Opus and combined video-to-MP3 conversion, complete audio duration, private cookie copies, proxy forwarding, saved format validation and file size enforcement.
- `php tests/quality_worker.php`, `--audio` and `--shorts`: link inspection, conversion of the same text message into a poster, quality/audio choice, button removal, actual multipart delivery, duration and the blue source link, then deleting the entire poster message after delivery. A strict local API rejects text edits on photo messages.
- `php tests/quality_worker.php --legacy-caption` repeats the real upload path after upgrading a database with the historical caption, checking that rich metadata and the blue URL button belong to the delivered video.
- `php tests/quality_worker.php --custom-parts`, `--audio --custom-parts` and `--group --audio --custom-parts` verify separately customized captions and source buttons on video and audio uploads to the local test endpoint, including a group topic.
- `php tests/quality_worker.php --group` and `--group --audio`: real MP4/MP3 multipart delivery into the original group topic. `--group --disabled` verifies the real worker rejects queued group work before invoking YouTube and edits the existing group status without uploading or redirecting to private chat.
- PHP and Bash syntax, Compose configuration and production Docker build.
- `bash tests/manager.sh`: real step-process I/O, failure recovery, plain/color output, mixed service state, submenu Back/EOF behavior and operation-lock contention.
- `test_maintenance.py`: private backup round trips, invalid archive rejection, settings validation, stopped-service preservation and rollback on failed settings/restore application.
- `test_updater.py`: recovery and rollback, tracking a reopened progress menu, and rebuilding outdated or missing services even when the Git checkout is already current. Rebuilding is skipped only when both running application versions also match.
- `integration_maintenance.py`: after the production image build, an isolated CI Compose volume verifies actual SQLite/cookie backup and restore with runtime UID 10001; it makes no Telegram requests.

The media test replaces YouTube transport with local fixtures and Telegram with a local HTTP endpoint. It does not prove that a deployment's IP can access YouTube or that its bot token can upload to Telegram.

For deployment verification, start a conversation with the bot, then select **Diagnostics → Delivery test** in the server manager and paste a public YouTube URL. Success means Telegram accepted the actual MP4 upload to the first configured administrator.

When a job fails, `docker compose logs --tail=80 worker` includes a sanitized error and its processing stage. The administrator's `/health` command shows the corresponding Persian explanation and private usage statistics. Tokens and signed media URLs are redacted from process diagnostics.

Delivery optimizations and the scope of local timing measurements are documented in [performance notes](docs/performance.md). Worker regressions also validate per-stage timing logs; job tests cover selected-media priority and promotion of older inspections.

`php tests/quality_worker.php --cleanup-failure` checks that a rejected cover deletion keeps the completed delivery successful and does not upload the media again. Normal video/audio/group modes verify that only the original status message is deleted, after the file upload.

`php tests/parallel_worker.php` and `--group` hold a real 1080p multipart upload open while three further links obtain independent quality menus. They prove three simultaneous uploads for one user, a reserved inspection lane at full media capacity, automatic queue draining, distinct status/topic destinations, duplicate supervisor rejection, single-slot configuration, restart safety and recovery of a slot after a child is killed without retrying its uncertain upload. The PHP runtime requires `pcntl` and `posix`; the production image installs process control.

`php tests/cookie_manager.php` covers the service reply keyboard, private administrator authorization, metadata-only view, explicit protected in-memory exports, deletion confirmation/cancellation/expiry, changed-jar protection and stale-refresh suppression. `php tests/downloader_access.php` verifies direct yt-dlp inspection/video/audio with and without cookies, exact format/proxy preservation, private jars, successful refresh, forced cookie-import validation and failures without a second provider. The media suite also sends a real in-memory cookie document to a local multipart endpoint.

`php tests/quality_worker.php --anonymous`, `--anonymous --audio`, and `--anonymous --group` run the direct cookie-free yt-dlp path through fixture delivery. `php tests/parallel_worker.php --anonymous` covers concurrent cookie-free delivery. Node remains in the runtime image for yt-dlp's YouTube JavaScript support.

`php tests/instagram.php` covers canonical post/Reel URLs, rejected hosts, independent private cookies, expired/foreign imports, reply navigation, metadata-only viewing, protected exports, deletion races, administrator authorization, neutral Personalization controls and the media queue without quality callbacks.

`php tests/article_transport.php` starts a local TLS server with ALPN that deliberately resets HTTP/2 streams. It reproduces curl error 92, verifies article/account creation and multipart media uploads over HTTP/1.1 exactly once, and rejects an untrusted certificate. The fixture uses a generated local CA certificate with verification enabled. HTTP/2 reproduction is explicitly skipped if the installed libcurl has no HTTP/2 support; HTTP/1.1 and certificate checks still run.

The Instagram media regression also returns a real HTTP 412 from the local Catbox endpoint and verifies one rejected attempt followed by Qu.ax `files[]` multipart uploads for the remaining mixed-media article. It covers fallback failures, rejected external URLs, and transport/5xx failures that must not trigger fallback. No public hosting API is contacted by these regression tests.

The same regression checks the default native carousel through real multipart Telegram requests: first-slide-only delivery, durable next-page callbacks, mixed photo/video order, original topic, owner and access checks, repeated/stale clicks, processing limits, one-day expiration, cache removal, terminal uncertain uploads, and switching to the retained article mode. No public Telegram API is contacted.

`php tests/instagram_media.php` uses the actual pinned gallery-dl Instagram parser, item iterator, CLI, HTTP downloader and metadata postprocessors against raw local API responses. Real JPEG and H.264 files with and without audio pass through FFmpeg and actual multipart uploads to a local Telegram/media-host/API server. It verifies music-bearing photos/Reels, separate music records, 20-slide carousels, preservation of a video's soundtrack, rejection of genuinely missing slides, private/group delivery, forum topics, private cookie copies, ordered mixed-media articles, original captions as text nodes, customization, account reuse and provider failures without a false article link. It requires gallery-dl 1.32.19; set `GALLERY_DL_PYTHON` to its virtualenv Python when testing outside Docker. These tests do not verify live Instagram, Telegraph or Catbox access from a deployment.
